# 개발자 문서

코드를 고치거나 기능을 더하려는 사람을 위한 문서입니다. 설치와 실행은 [README](../README.md)를 먼저 봐 주세요.

## 1. 파일 구조

```
app.py              Flask 서버. 화면 하나(index.html)와 /api/* 를 제공
checker.py          판별 로직. 넥슨 API를 어떤 순서로 부르고 결과를 어떻게 묶는지
nexon.py            넥슨 Open API 클라이언트 (재시도, 오류 메시지)
vision.py           스크린샷에서 닉네임 읽기 (Claude API)
db.py               SQLite 저장소 (설정, 계정, 캐시, 검색 기록, 업데이트 내역)
changelog.py        업데이트 내역: CHANGELOG.md 초안 읽기, 관리 목록 만들기
CHANGELOG.md        업데이트 내역 초안 (게시해야 화면에 보임)
templates/index.html  페이지 뼈대 (처음 화면 + 탭 4개)
static/app.js       화면 로직 (빌드 도구 없이 그대로 씀)
static/style.css    스타일 (라이트/다크)
static/logo.svg     로고·파비콘
tests/              가짜 넥슨 서버와 테스트
```

화면은 페이지 하나에 탭을 바꿔 가며 보여 주는 방식입니다. 주소 뒤의 `#members`, `#chars`, `#guild`, `#settings` 로 탭이 정해집니다. 위쪽 버전 표시를 누르면 `#changelog`(업데이트 내역)로 갑니다.

## 2. 탭별 동작

| 탭 | 화면 | 서버 |
|---|---|---|
| 길드원 검색 | 검색 버튼, 진행률, 결과 카드, 지난 기록 | `POST /api/scan` (mode `ours`) → 백그라운드 작업 → 1초마다 `GET /api/jobs/<id>` |
| 캐릭터명 검색 | 스크린샷 올리기 → 닉네임 읽기 → 텍스트 상자에서 고치기 → 조회 | `POST /api/read-image`, `POST /api/lookup` (바로 응답) |
| 길드 검색 | 아무 길드의 길드원 캐릭터 조회만 (판정 없음), 찾을 캐릭터가 목록에 있는지 | `POST /api/scan` (mode `other`) → 결과는 저장하지 않고 작업에 담아 돌려줌 |
| 설정 | API 키, 우리 길드, 모델, 계정 관리, 업데이트 내역 관리 | `/api/settings`, `/api/users`, `/api/changelog` … |

의심 결과의 [길드 검색] 버튼은 `#guild?w=월드&g=길드&f=찾을캐릭터` 주소로 이동하고, 길드 검색 탭이 이 값을 채워서 바로 검색합니다.

## 3. 판별 방식

### 같은 계정 묶기
넥슨 API로는 한 계정의 캐릭터 목록을 알 수 없습니다. 대신 유니온 랭킹(`/ranking/union`)에 캐릭터 ocid를 넣으면 그 계정의 **유니온 대표 캐릭터**가 나옵니다. 같은 월드, 같은 계정이면 어느 캐릭터로 물어도 대표가 같으므로 대표 이름으로 묶습니다.

- 유니온 랭킹은 하루 단위 데이터입니다 (어제 기준, 새벽 2시 전이면 그제).
- 랭킹에 없는 계정이나 없는 캐릭터는 '판별 불가'로 따로 모읍니다.

### 검색 전 정보 갱신
`/character/basic`, `/guild/basic` 은 `date` 없이 부르면 최신 정보를 줍니다. 검색할 때는 항상 이렇게 다시 받습니다 (`Scanner.fresh`). 최신 정보를 못 받으면 어제 기준 정보로 대신하고 화면에 '어제 기준'이라고 표시합니다.

### 다른 길드 대조
캐릭터 정보에 우리 길드가 아닌 다른 길드가 나오면, 그 길드의 길드원 목록을 받아 실제로 있는지 봅니다 (`Scanner.verify`).

| 상태 | 뜻 | 화면 |
|---|---|---|
| `confirmed` | 그 길드 목록에도 있음 | 포착 |
| `stale` | 목록에는 없음. 캐릭터 정보가 옛날 것 | 이미 나간 것으로 보임 — **의심에서 뺌** |
| `unknown` | 길드 목록을 못 받음 | 확인 불가 — 메애기 링크 |

캐릭터 정보는 그 캐릭터로 접속해야 갱신되지만, 길드원 목록은 강퇴나 탈퇴가 바로 반영됩니다. 그래서 둘이 다르면 **길드원 목록을 더 믿습니다.** 예를 들어 강퇴당한 뒤 접속하지 않은 캐릭터는 캐릭터 정보에 옛 길드가 남아 있지만 그 길드 목록에는 없습니다. 이런 경우 `left_guild` 에 그 길드를 적고 의심(`dual`)에서 뺍니다. 확실히 하려면 그 캐릭터로 한 번 접속해 달라고 하면 됩니다.

### 길드원 검색 순서 (`Scanner.run`)
1. 길드 정보와 최신 길드원 목록
2. 길드원 전원 최신 정보 갱신
3. 길드원마다 유니온 대표
4. 길드 밖에 있는 대표의 최신 정보 → 다른 길드면 그 길드 목록과 대조
5. (선택) 30일 성장 확인: 대표의 30일 전 레벨·경험치와 비교
6. 심층: 대표가 가 있는 의심 길드의 길드원 전부의 대표를 확인해서 숨은 부캐 찾기
7. (선택) 역방향: 길드 랭킹 상위 N개 길드까지 같은 방식으로 확인

같은 이름이나 같은 ocid는 한 번의 검색 안에서 한 번만 부르도록 `Scanner._once` 로 막습니다. 넥슨 호출은 `WORKERS` 개씩 동시에 합니다.

### 캐릭터명 검색 (`checker.lookup`)
이름마다 최신 정보 → 대표 → 대표의 길드를 확인하고, 우리 길드가 아닌 길드가 나오면 위와 같이 대조합니다. 넣은 이름들의 대표가 몇 개인지(= 계정 수)도 돌려줍니다. 핸즈 캐릭터 목록이면 1개여야 정상입니다.

### 잘못 읽은 닉네임 바로잡기
이미지 인식은 '뇬', '쀼' 같은 드문 글자를 '논', '뿌' 같은 흔한 글자로 읽는 경우가 많습니다. 없는 이름이 나오면 헷갈리기 쉬운 자모를 바꾼 후보를 만들어 넥슨에서 찾아봅니다 (`hangul_variants`, `suggest_fixes`).

- 바꾸는 자모: 모음 ㅏ/ㅑ, ㅓ/ㅕ, ㅗ/ㅛ, ㅜ/ㅠ, ㅐ/ㅒ, ㅔ/ㅖ, ㅔ/ㅐ, 초성 ㄱ/ㄲ, ㄷ/ㄸ, ㅂ/ㅃ, ㅅ/ㅆ, ㅈ/ㅉ, 받침 ㅅ/ㅆ, ㄱ/ㄲ
- 한 글자 바꾸기 + 모음 두 개 바꾸기, 이름 하나당 최대 40개
- 찾은 캐릭터의 대표가 목록의 주 계정과 같으면 '같은 계정'으로 표시합니다.

## 4. 스크린샷 닉네임 읽기 (`vision.py`)

- 여러 장을 Claude 한 번 호출로 보냅니다 (최대 10장, 한 장 5MB).
- 화면에서 긴 변 2576px, 375만 화소까지 맞춰서 보냅니다. 작은 스크린샷은 최대 2배까지 키웁니다. 글자가 작으면 모음의 짧은 획을 놓치기 쉽기 때문입니다.
- 응답은 JSON 스키마로 받습니다: 캐릭터마다 `name`, `level`, `world`, `guild`, `unsure`, 그리고 화면에 적힌 캐릭터 수 `shown_count`, 메모 `note`.
- 읽은 이름은 그대로 믿지 않고, 사람이 텍스트 상자에서 고친 뒤 넥슨 API로 다시 확인합니다.

## 5. 사용 방식과 계정

처음 접속할 때 고르고 `app_config.mode` 에 저장합니다.

| | `solo` (혼자 쓰기) | `shared` (같이 쓰기) |
|---|---|---|
| 로그인 | 없음 | Flask 세션 쿠키 (30일, `SameSite=Lax`) |
| 계정 | 없음. 모든 데이터가 user 0 | 처음 고른 사람이 관리자. 관리자가 계정 추가 (회원가입 없음) |
| 넥슨 키 | 설정 → 없으면 `.env` | 계정마다 설정 (`.env` 안 씀) |
| Claude 키 | 설정 → 없으면 `.env` | 개인 키 → 없으면 `.env` 공용 키 |

- 비밀번호는 `werkzeug.security` 해시로만 저장합니다. 로그인에 실패하면 1초 쉬고 응답합니다.
- 세션 서명 비밀값은 처음 실행할 때 만들어 `app_config.secret_key` 에 둡니다. 서버를 다시 켜도 로그인이 유지됩니다.
- `solo` 에서 `shared` 로 바꾸면 user 0의 설정과 기록이 새 관리자 계정으로 옮겨집니다.
- 설정 API는 키 전체를 돌려주지 않고 앞뒤 몇 글자만 보여 줍니다. 공용 키는 그것도 보여 주지 않습니다.

## 6. 서버 API

모든 `/api/*` 는 JSON입니다. 사용 방식을 아직 안 골랐거나 로그인하지 않았으면 `401` 과 `{"setup": true}` 또는 `{"login": true}` 를 돌려줍니다.

| 메서드 | 주소 | 하는 일 |
|---|---|---|
| GET | `/api/status` | 사용 방식, 로그인한 계정 |
| POST | `/api/setup` | 사용 방식 고르기 (shared면 관리자 아이디·비밀번호) |
| POST | `/api/login`, `/api/logout` | 로그인, 로그아웃 |
| POST | `/api/me/password` | 내 비밀번호 바꾸기 |
| GET, POST | `/api/users` | 계정 목록, 계정 추가 (관리자) |
| POST | `/api/users/<id>/password` | 비밀번호 초기화 (관리자) |
| DELETE | `/api/users/<id>` | 계정 삭제 (관리자, 그 계정의 설정·기록도 삭제) |
| GET, POST | `/api/settings` | 내 설정 보기, 저장 (`clear_nexon_key`, `clear_claude_key` 로 키 지우기) |
| POST | `/api/settings/test` | 넥슨 키로 우리 길드 찾아보기 |
| POST | `/api/scan` | 길드원 검색(`mode: ours`) / 길드 검색(`mode: other`) 시작 |
| GET | `/api/jobs/current`, `/api/jobs/<id>` | 진행 중인 작업, 진행률 |
| POST | `/api/jobs/<id>/cancel` | 작업 멈추기 |
| GET, DELETE | `/api/scans`, `/api/scans/<id>` | 지난 검색 기록 (지난번과 비교 `diff` 포함) |
| POST | `/api/lookup` | 캐릭터명 검색 (`names`: 줄바꿈으로 구분, 최대 60명) |
| POST | `/api/read-image` | 스크린샷 읽기 (`multipart`, `images` 여러 개) |
| GET | `/api/version` | 게시한 업데이트 내역과 지금 버전 (로그인 없이) |
| GET | `/api/changelog` | 초안 + 저장·게시한 글 목록 (혼자 쓰기 또는 관리자) |
| PUT, DELETE | `/api/changelog/<버전>` | 문구·날짜 저장, `published`/`hidden` 바꾸기 / 게시 취소 |

검색 작업은 계정마다 한 번에 하나만 돌 수 있습니다. 작업 상태는 메모리에만 있고 서버를 다시 켜면 사라집니다. 결과는 DB에 남습니다.

### 쓰는 넥슨 API

| 주소 | 용도 |
|---|---|
| `/id` | 캐릭터 이름 → ocid |
| `/character/basic` | 길드, 레벨, 직업, 이미지, 월드 (date 없이 = 최신) |
| `/ranking/union` | ocid → 그 계정의 유니온 대표 |
| `/guild/id`, `/guild/basic` | 길드 이름 → id → 길드원 목록 (date 없이 = 최신) |
| `/ranking/guild` | 역방향 검색할 길드 목록 (주간 명성치 순) |

명세: https://openapi.nexon.com/ko/game/maplestory/

## 7. DB (`data/guild.db`)

| 테이블 | 내용 |
|---|---|
| `app_config` | 사용 방식(`mode`), 세션 비밀값 |
| `users` | 계정 (아이디, 비밀번호 해시, 관리자 여부) |
| `user_settings` | 계정별 설정. 혼자 쓰기는 user_id 0 |
| `scans` | 지난 검색 결과 (JSON), `owner` 로 계정 구분 |
| `ocid_cache` | 이름 → ocid (30일, 못 찾음은 1일) |
| `rep_cache` | ocid → 유니온 대표 (`REP_TTL_DAYS`, 기본 3일) |
| `char_cache` | 날짜별 캐릭터 정보 (어제 기준·30일 전 비교용) |
| `guild_cache`, `guild_members` | 길드 이름 → id (30일), 날짜별 길드원 목록 |
| `changelog_posts` | 업데이트 내역: 관리자가 다듬어 저장·게시한 글 (`published`, `hidden`) |
| `settings` | 예전 버전의 설정. 처음 실행할 때 `user_settings` 로 옮깁니다 |

예전 DB를 열면 `Store._migrate` 가 필요한 칸을 추가하고 설정을 옮깁니다. 60일 넘은 날짜별 캐시는 서버를 켤 때 지웁니다.

## 8. 넥슨 API 사용량

캐릭터·길드 정보는 매번 최신으로 다시 받고, ocid(30일)와 유니온 대표(3일)는 캐시합니다. 그래서 첫 검색만 많고 이후는 적습니다. 결과 화면 오른쪽 위에 실제 호출 수가 나옵니다.

### 길드원 검색
M 우리 길드 캐릭터 수, A 계정 수, O 길드 밖 대표 수, G 의심 길드 수, S 의심 길드 길드원 합계, N 역방향 길드 수, T 그 길드원 합계

| 언제 | 호출 |
|---|---|
| 매번 | 길드 정보 `1 + G (+N)`, 캐릭터 최신 정보 `M + O (+찾은 부캐)`, 길드 랭킹 `⌈N/200⌉` |
| 그날 첫 검색 (30일 성장 켬) | 30일 전 정보 `A` |
| 대표 캐시가 없을 때 (처음, 3일마다) | 유니온 대표 `M + S (+T)` |
| ocid 캐시가 없을 때 (처음, 30일마다) | ocid `M + O + S (+T)`, 길드 id `1 + G (+N)` |

예) 캐릭터 200, 계정 70, 길드 밖 대표 10, 의심 길드 3개(길드원 600)

| | 역방향 끔 | 상위 50 (약 7,500명) | 상위 200 (약 30,000명) |
|---|---|---|---|
| 처음 | 약 1,900 | 약 17,000 | 약 62,000 |
| 3일 안에 다시 | 약 220~290 | 약 270~340 | 약 420~490 |
| 3일 지나서 | 약 1,100 | 약 8,600 | 약 31,000 |

### 캐릭터명 검색 (이름 K개)
처음 약 `3K` (+ 의심 길드마다 2), 3일 안에 다시 약 `K + 1`. 잘못 읽은 이름은 하나당 최대 40번 더 (보통 5~15).

### 길드 검색 (그 길드 캐릭터 M')
판정 없이 조회만 하므로 유니온 랭킹을 부르지 않습니다. 처음 약 `2 + 2M'`, 다시 약 `1 + M'`.

이 공식은 가짜 넥슨 서버로 실제 호출 수를 세서 맞는지 확인했습니다. 넥슨이 `429 OPENAPI00007` 을 주면 잠깐 쉬었다가 다시 시도합니다 (`nexon.Client.get`).

## 10. 화면 규칙

- 그라데이션 없이 단색만 씁니다. 색은 `style.css` 맨 위의 CSS 변수로만 정합니다.
- 라이트/다크 두 가지를 다 맞춥니다 (`:root`, `[data-theme="dark"]`, `prefers-color-scheme`).
- 제목·탭·큰 숫자는 메이플스토리체(넥슨 무료 서체, 눈누 CDN), 본문은 Pretendard / 맑은 고딕.
- 폰 화면(폭 640px 이하)과 터치 기기(`pointer: coarse`)를 따로 맞춥니다. 폰에서는 사진 올리기가 '갤러리 열기' 버튼 하나로 바뀝니다.
- 정적 파일 주소에는 수정 시각을 붙여서(`?v=`) 업데이트 후 예전 파일이 캐시에 남지 않게 합니다.
- 검색어 입력칸은 글자를 칠 때 다시 만들지 않고 목록만 다시 그립니다. 입력칸을 새로 만들면 한글 조합이 끊겨 'ㅁㅜㄴㅣ'처럼 써집니다.

## 11. 알려진 한계

- 유니온 대표가 꼭 본캐는 아닙니다 (게임에서 바꿀 수 있음). 같은 계정인지 가리는 데는 문제없습니다.

- 역방향 검색은 길드 랭킹 상위 길드만 봅니다. 그 밖의 작은 길드에 있는 부캐는 못 찾습니다.
- 넥슨 정보는 캐릭터로 접속해야 갱신되므로, 결과는 경고로만 봐야 합니다.
